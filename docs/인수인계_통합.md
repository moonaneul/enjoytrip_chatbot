## 3. 개발자 2가 바꿔야 할 것

### 3-1. `servers/main.py` — 요청 모델

```python
# 지금
class ChatReq(BaseModel):
    message: str
    use_rag: bool = False

# 필요
class ChatReq(BaseModel):
    message: str
    traveler_type: Literal["senior", "baby", "both"]
    needs: list[str] = []
    current_place_id: str | None = None
```

프런트는 `use_rag`를 **보내지 않습니다.** RAG 상시 실행은 서버가 보장해 주세요.

### 3-2. `/chat` 응답

`{answer, source}` → 아래 구조로 교체합니다. 전체 예시는 `clients/README.md`의 Shared API Contract 절에 있습니다.

```
success  place  comfort  sections  facilities  unknown_fields  sources  suggested_questions
```

업무 오류(장소 못 찾음 등)도 **HTTP 200 + `success:false`** 로 주세요. HTTP 4xx/5xx는 화면에서 서버 장애로 처리합니다.

### 3-3. enum 확정

```
comfort.level          COMFORTABLE / CHECK_NEEDED / BURDEN_POSSIBLE / INSUFFICIENT_DATA
comfort.items[].status SATISFIED / UNSATISFIED / UNKNOWN
error.code             PLACE_NOT_FOUND / AMBIGUOUS_PLACE
```

프런트는 `NOT_SATISFIED` `CAUTION` `NOT_FOUND` `PLACE_AMBIGUOUS` `MULTIPLE_PLACES`도 방어적으로 받지만, 팀 표준은 위 세 줄로 통일합니다.

### 3-4. 답변 말투

`docs/프롬프트_v2_UIUX개선.md` **16번의 시스템 프롬프트 원문**을 답변 생성 프롬프트에 넣어 주세요.
화면 문구를 아무리 다듬어도 `answer`와 `comfort.items[].reason`이 보고서투면 사용자에게는 그대로 보입니다.

계약 검사기가 아래를 자동으로 잡아 줍니다.

```
에 대해 / 에 관하여 / 제공됩니다 / 지원합니다 / 확인할 수 있습니다 /
판단됩니다 / 되어집니다 / 귀하 / 당신 / 해당 시설 / 본 서비스 …
```

### 3-5. v1부터 남아 있는 서버 이슈

```
· shutdown 시 shutil.rmtree(CHROMA_DB_PATH) — 캐시가 매번 사라집니다
```

## 5. 지도 링크에 대해 (v3에서 추가)

시설 카드에 `카카오맵에서 열기` 링크가 붙습니다. **서버가 할 일은 없습니다.**

```
지도 SDK · 인증키 · 좌표  →  쓰지 않습니다
링크 URL                  →  프런트가 map_search_text를 인코딩해서 만듭니다
```

다만 두 가지는 서버 품질에 달려 있습니다.

1. `map_search_text`에 **내부 위치를 섞지 마세요.** `국립중앙박물관 어린이박물관 1층 수유실`은 지도에서 안 나옵니다.
   `관광지명 + 주소` 형태로 주세요. 내부 위치는 `location_detail`에 따로 담으면 화면이 나눠 보여 줍니다.
2. `facility.type`을 `restroom` `nursing_room` `diaper_station` `parking` `rest_area` `elevator` 중 하나로 주면
   아이콘이 정확히 붙습니다. 다른 값이면 기본 핀으로 그리므로 필수는 아닙니다.

계약 검사기가 1번을 `[필수]` 위반으로 잡습니다.

`clients/tests/QA.md`의 Persona 1~17번을 **실제 서버로** 돌리면서 아래를 같이 봅니다.

```
[ ] 자료에 없는 시설을 지어내지 않는가 (Hallucination)

[ ] 주소·시설명을 원본 그대로 쓰는가
[ ] comfort.level 규칙 결과와 answer 문장이 서로 어긋나지 않는가
[ ] 같은 이름의 관광지에서 지역을 되묻는가

[ ] answer가 두 문장 이내인가
```

앞 네 줄은 RAGAS로 잡히지 않습니다. 사람이 봐야 합니다.

## 8. 자주 어긋나는 다섯 가지

실제로 통합할 때 여기서 시간이 가장 많이 샙니다.

1. **업무 오류를 4xx로 보냄** → 화면이 서버 장애로 처리해 재시도 버튼만 뜹니다. 200 + `success:false`로 주세요.
2. **`sections[].items[].value`에 숫자나 객체를 담음** → 화면 표시용 문자열이어야 합니다.
3. **`comfort.items` 순서가 무작위** → 앞 3개만 카드에 바로 보입니다. 중요한 것을 앞에 담아 주세요.
4. **`answer`가 다섯 문장** → 카드 요약 자리가 길어져 아래 정보가 밀립니다. 두 문장 이내.
5. **`map_search_text`에 내부 위치 포함** → 지도에서 검색이 안 됩니다.

# Front v5 + Backend v11 통합 인수인계

## 기준본

- `clients/`: 개발자 1 Front v5를 Backend v11 계약에 맞춰 수정한 통합본
- `servers/`: 개발자 2 Backend v11 기반
- `/chat`: `{ message, traveler_type, needs, current_place_id }`

## 확정 NeedType

- `walking_difficult`
- `stairs_difficult`
- `need_rest_area`
- `wheelchair_needed`
- `restroom_important`
- `stroller`
- `need_nursing_room`
- `need_diaper_station`
- `need_elevator`

`long_walk_difficult`는 Front localStorage 로딩 시 `walking_difficult`로 마이그레이션합니다. `driving`은 Comfort Need에서 제거했습니다. 주차는 자유 질문 및 `sections`/`facilities`로 표시합니다.

## Comfort status

- `SATISFIED`
- `CONFLICT`
- `UNKNOWN`

Front는 과거 alias도 방어적으로 렌더링하지만 신규 계약은 위 3종입니다.

## AMBIGUOUS_PLACE

Backend의 `candidates[]`를 Front가 직접 버튼으로 표시합니다. 후보 선택 시 이름을 다시 검색하지 않고 해당 `content_id`를 `current_place_id`로 보내 장소를 확정합니다.

## Follow-up

성공 응답의 `place.content_id`를 Front가 상태로 보관하고, 추천 질문 및 일반 후속 질문에서 `current_place_id`로 재사용합니다.

## 지도

Front는 `facilities[].map_search_text`만 사용해 카카오맵/네이버지도/구글지도 링크를 생성합니다. 내부 위치(`location_detail`)를 검색어에 합치지 않습니다.

## 실행

Backend:
```powershell
cd servers
uvicorn main:app --reload
```

Front:
```powershell
python -m http.server 5500 --bind 127.0.0.1 --directory clients
```

Contract check:
```powershell
node clients\tests\contract-check.mjs
```


## integrated v2 UI/UX 변경

1. 폰트: 기존 `우리 가족 조건` 제목에 쓰던 Gaegu를 전역 폰트로 승격했습니다.
2. 초기 장소 칩: 2개에서 6개로 확대하고 클릭 즉시 `/chat` 요청을 보냅니다.
3. 중복 onboarding 방지: 가족 유형을 다시 눌러도 장소 안내 봇 카드가 한 개만 남습니다.
4. 추천 질문: sticky 입력창 위에서 교체하지 않고 각 결과 카드 하단에 고정합니다. 클릭은 새 대화 turn을 추가합니다.
5. 결과 요약: 긴 `answer` 원문 대신 구조화 필드로 최대 1~2문장만 생성해 표시합니다.
6. 내부 Rule Engine 문구는 기본 화면에 노출하지 않습니다.
7. 사진 3 계열의 조건 카드/시설 카드/지도/더보기 디자인은 유지합니다.
8. `다른 곳 보기`와 `조건 바꾸기`를 결과 하단의 탐색 행동으로 제공합니다.

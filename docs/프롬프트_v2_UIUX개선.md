==================================================
2. 이번 개선의 한 줄 목표
==================================================

> **조건을 다 채워야 쓸 수 있는 화면**에서
> **일단 물어보면 답이 나오는 화면**으로 바꾼다.

기준 사용자는 IT에 익숙하지 않은 40~60대 보호자다.
이 사람이 설명 없이 30초 안에 첫 답을 받으면 성공이다.

==================================================
3. 반드시 지킬 설계 원칙
==================================================

**3-1. 경로 — 최단 동선**

첫 화면에서 답까지 필요한 조작은 **최대 2번**이다.
`(질문 입력 → 전송)` 또는 `(칩 하나 누름 → 전송)`.
그 이상을 요구하는 단계는 전부 뒤로 미루거나 없앤다.

**3-2. 일관성**

같은 뜻은 같은 위치·같은 모양·같은 말로만 표현한다.
- 봇이 말하는 것은 전부 대화 흐름 안에서 왼쪽 정렬 말풍선/카드
- 사용자가 누르는 제안은 전부 같은 모양의 칩
- 오류도 예외가 아니다. 대화 밖에 뜨는 별도 패널을 만들지 마라

**3-3. 점진적 공개**

처음에 다 보여주지 않는다.
`꼭 필요한 것 → 눌러야 보이는 것 → 접혀 있는 것` 3단으로 나눈다.

**3-4. 판단은 서버, 표현만 화면**

편안함 등급, 시설 존재, 주소는 절대 프런트에서 만들지 않는다.
이 원칙은 v1 그대로 유지한다.

==================================================
4. 화면 구조 개편 — MUST
==================================================

**4-1. 2단 → 1단**

`.workspace`의 좌우 2단을 없앤다. 화면은 위에서 아래로 하나의 흐름이다.

```
헤더(로고 + 한 줄)
  ↓
인사 + 대화 영역          ← 여기가 화면의 주인공
  ↓
추천 칩
  ↓
입력창 (모바일에서는 하단 고정)
```

**4-2. 히어로 축소**

현재 히어로는 화면 절반을 쓴다. 제목 한 줄 + 부제 한 줄로 줄인다.
일러스트는 남기되 높이를 줄이거나, 좁은 화면에서는 숨긴다.

기준: **모바일 390×844에서 스크롤 없이 입력창이 보여야 한다.**

**4-3. 중첩 스크롤 제거**

`.chat-window`의 `max-height` / `overflow-y:auto`를 없앤다.
스크롤은 페이지 하나만 존재한다.
대신 새 답변이 오면 그 답변의 제목이 화면 상단에 오도록 스크롤한다.
(기존 `showLatestAnswer()` 의도를 살려서 다시 구현)

**4-4. `01` / `02` 스텝 라벨 삭제**

단계 번호는 "아직 다 안 했다"는 압박을 준다. 전부 없앤다.

**4-5. 모바일 입력창 고정**

```css
position: sticky; bottom: 0;
padding-bottom: max(12px, env(safe-area-inset-bottom));
```
가리는 만큼 대화 영역 아래 여백을 준다.

==================================================
5. 시작 흐름 — 설정 화면을 대화로 바꾼다 (MUST)
==================================================

**5-1. 첫인사는 짧게, 봇의 첫 말풍선으로**

현재의 `.welcome` 블록(제목+설명+예시2개+각주)은 정보가 많다.
아래 3줄로 줄이고, 대화 안 첫 메시지로 보여준다.

```
안녕하세요, 온이예요.
가고 싶은 곳을 알려주시면 우리 가족이 다니기 편한 곳인지 같이 살펴볼게요.

누구랑 가세요?
[ 부모님과 ]  [ 아이와 ]  [ 다 같이 ]
```

**5-2. 가족 유형 선택을 관문으로 쓰지 마라 — 가장 중요**

`script.js:242`의 차단 로직을 없앤다.
유형을 안 골라도 질문은 전송된다.
유형 정보가 없으면 봇이 대화 안에서 되묻는다.

```
사용자: 경복궁 우리 엄마랑 가도 될까?
온이  : 부모님과 가시는 거군요. 맞을까요?
        [ 네, 부모님과 ]  [ 아이도 같이 가요 ]
```

칩을 누르면 **직전 질문을 그대로 다시 보낸다.** 사용자가 다시 타이핑하지 않는다.

**5-3. 유형을 고르면 곧바로 다음 행동으로**

선택 즉시 봇이 한 줄로 받아주고 추천 칩을 띄운다. 설정 화면으로 되돌리지 마라.

```
온이: 부모님과 함께시군요. 어디 가시는지 알려주세요.
      [ 경복궁 ]  [ 국립중앙박물관 ]  직접 입력
```

==================================================
6. 조건 선택 간소화 — MUST
==================================================

**6-1. 처음에 체크박스를 0개 보여준다**

시작 화면에서 조건 목록을 펼치지 않는다.

**6-2. 유형별 기본값을 자동 적용한다**

사용자가 아무것도 안 해도 아래가 `needs`로 전송된다.

```
senior → stairs_difficult, need_rest_area, restroom_important
baby   → stroller, need_nursing_room, need_diaper_station
both   → stairs_difficult, need_rest_area, restroom_important, stroller, need_nursing_room
```

Backend 계약(`needs` key 목록)은 v1 그대로다. 전송 방식만 바뀐다.

**6-3. 상세 조정은 접어 둔다**

대화 영역 위에 한 줄짜리 요약 버튼을 둔다.

```
우리 가족 조건 · 계단, 휴식, 화장실   [ 바꾸기 ]
```

`바꾸기`를 누르면 조건이 펼쳐진다(모바일은 바텀시트, 데스크톱은 인라인 펼침).
- 체크박스가 아니라 **누르면 켜지는 칩**으로 만든다
- 한 화면에 최대 6개. `both`의 10개는 자주 쓰는 6개만 노출하고 나머지는 `+ 더보기`
- 닫으면 요약 문장이 갱신되고, 다음 질문부터 반영된다고 한 줄로 알린다

**6-4. 조건은 답을 받은 뒤에 권한다**

첫 답변 아래에 칩 하나를 붙인다.

```
[ 조건 더 알려주고 다시 보기 ]
```

먼저 답을 주고, 정교화는 그다음이다. 순서를 뒤집지 마라.

==================================================
7. 답변 카드 3층 구조 — MUST
==================================================

지금은 편안함·이동·부모님·아이·시설·미확인·출처·추천이 한꺼번에 펼쳐진다.
아래 3층으로 다시 짠다.

**1층 — 항상 보인다 (결론)**

```
경복궁
ⓘ 방문 전 확인할 정보가 있어요
계단 구간이 있어서 우회로를 미리 봐두시면 좋아요.
```

- 장소명, 편안함 배지(아이콘+색+텍스트 3중 표기 유지), 한 문장 요약
- 요약은 **두 문장을 넘기지 않는다**

**2층 — 항상 보인다 (내 조건 결과, 최대 3줄)**

```
✓ 화장실  이용할 수 있어요
✓ 쉴 곳    휴식 공간이 있어요
?  계단    자료에 안 나와 있어요
```

- `comfort.items` 중 앞에서 3개까지. 나머지는 3층으로
- 상태 문구는 `✓ / ? / !` 와 텍스트를 함께 쓴다

**3층 — 접어 둔다**

```html
<details>
  <summary>자세히 보기</summary>
  …이동·부모님·아이·편의시설 섹션, 미확인 정보, 출처…
</details>
```

- `<details>`는 기본으로 닫혀 있다
- 미확인 정보와 출처는 3층 맨 아래. 신뢰를 위해 반드시 남기되 첫 화면을 차지하지 않는다
- **미확인을 없음으로 바꾸지 않는다.** v1 규칙 유지

**시설 카드**

- 2개까지만 먼저 보여주고 나머지는 `+ 시설 N곳 더 보기`
- 카드 안 순서: 시설명 → 어디 안 → 주소 → 복사 버튼

==================================================
8. 지도 검색어 복사 개선
==================================================

동작은 v1을 유지한다(서버 문자열 그대로, 3단계 fallback, `map_search_text` 없으면 버튼 숨김).
표현만 바꾼다.

- 버튼 라벨: `지도 검색어 복사` → **`주소 복사`**
- 버튼 아래 한 줄 안내: `복사해서 쓰시는 지도 앱에 붙여넣으세요.`
- 복사 성공 시 **버튼 자체가** `✓ 복사했어요` 로 2초 바뀐다
- 화면 구석 토스트와 버튼 안내를 동시에 띄우지 않는다. 하나만 쓴다
- 실패 시에만 직접 선택용 입력칸을 연다 (기존 로직 유지)

==================================================
9. 끼어들기 · 후속 질문 · 종료 (MUST)
==================================================

**9-1. 지금 어느 장소 얘기 중인지**

`place-context` 배너를 대화 밖 띠가 아니라 대화 안 시스템 줄로 바꾼다.

```
— 지금 경복궁에 대해 이야기하고 있어요   [ 다른 곳 보기 ]
```

**9-2. 답변 대기 중 새 질문이 들어오면**

지금은 전송이 막힌다(`state.busy`). 대신 이렇게 한다.

```
온이: 지금 경복궁을 보고 있는데, 새로 여쭤보신 것부터 볼까요?
      [ 새 질문 먼저 ]  [ 이거 먼저 볼게요 ]
```

새 질문을 먼저 처리했다면, 끝난 뒤 **기존 질문을 상기시킨다.**

```
온이: 아까 여쭤보신 경복궁 화장실도 이어서 볼까요?
      [ 네, 이어서 ]
```

둘 중 하나를 버리게 만들지 마라. 처음부터 다시 시키지도 마라.

**9-3. 종료·이탈을 분명히 인지시킨다**

`다른 장소 알아보기`를 누르면 대화에 구분선과 마무리 문장을 남긴다.

```
──────────────────────────────
경복궁 이야기는 여기까지예요. 다음은 어디로 가볼까요?
```

한 장소 대화를 3회 이상 주고받은 뒤 새 장소로 넘어가면 짧은 요약을 남긴다.

```
오늘 살펴본 곳 · 경복궁 (확인 필요 2가지)
```

==================================================
10. 답할 수 없을 때 (MUST)
==================================================

`이해할 수 없어요`, `찾을 수 없어요` 로 끝내지 마라.
아래 3요소를 **항상 함께** 낸다.

```
① 왜 안 되는지  ② 지금 할 수 있는 차선  ③ 누를 것 하나
```

| 상황 | 문구 |
| --- | --- |
| 장소 못 찾음 | `그 이름으로는 공식 자료에서 못 찾았어요. 지역을 같이 알려주시면 다시 찾아볼게요.` + `[ 지역 붙여서 다시 묻기 ]` |
| 이름이 여럿 | `같은 이름이 여러 곳이에요. 어디를 말씀하시는 걸까요?` + 지역 칩 |
| 자료에 없는 항목 | `수유실은 공식 자료에 안 나와 있어요. 대신 화장실이랑 휴식 공간은 확인돼요.` + `[ 그거 보여줘 ]` |
| 서비스 범위 밖 | `그건 제가 확인하기 어려워요. 대신 이동이랑 편의시설은 도와드릴 수 있어요.` + 추천 칩 |
| 서버 오류 | `잠깐 정보를 못 가져왔어요. 잠시 뒤 다시 눌러주세요.` + `[ 다시 시도 ]` |

**하지 말 것**: 사과 반복, `죄송합니다`로 시작하기, 실패 이유 없이 다시 하라고만 하기.

11. 퍼소나 — 온이
==================================================

```
이름   온이 (온가의 동행)
정체   여행 잘 다니는 조카. 안내 데스크 직원도, 명랑한 마스코트도 아니다
성격   차분하다. 앞서가지 않는다. 아는 것과 모르는 것을 분명히 나눈다
말투   해요체. 짧고 담백하게
태도   대신 판단해 주지 않는다. 판단할 재료를 정리해 준다
```

**온이가 하지 않는 것**

- 과장 (`완벽해요`, `최고예요`)
- 보장 (`안전합니다`, `문제없어요`, `걱정 마세요`)
- 감정 대변 (`힘드셨겠어요`, `속상하시죠`)
- 이모지 (본문에 0개. 아이콘은 UI 라벨에만)
- 자기 자랑 (`제가 다 찾아드릴게요`)

시각화는 이미 있는 온가 BI(잎사귀 초록, 종이질 배경)를 그대로 쓴다.
캐릭터 일러스트를 새로 그릴 필요는 없다. 로딩 인디케이터와 첫인사 아이콘 정도로 존재감을 준다.

12. 말투 규칙 — 번역투 제거 (MUST)
==================================================

화면 문구, 오류 문구, LLM 답변 **전부**에 적용한다.

**12-1. 금지 표현**

```
~에 대해 / ~에 관하여 / ~로부터 / ~을 통하여
~이 제공됩니다 / ~을 지원합니다 / ~이 가능합니다
~을 확인할 수 있습니다 / ~로 판단됩니다 / ~이 요구됩니다
~되어집니다 (이중피동) / ~하실 수 있으십니다 (과잉 존대)
귀하 / 당신 / 사용자님 / 고객님
해당 시설 / 본 서비스 / 상기 / 하기
```

**12-2. 이렇게 바꾼다**

| 번역투·보고서투 | 자연스러운 한국어 |
| --- | --- |
| 해당 관광지는 엘리베이터가 제공되고 있습니다. | 엘리베이터 있어요. |
| 휠체어 대여 가능 여부에 대한 정보가 확인되지 않습니다. | 휠체어를 빌릴 수 있는지는 자료에 안 나와 있어요. |
| 방문 전 확인이 필요할 것으로 판단됩니다. | 가시기 전에 한 번 확인해 보시면 좋아요. |
| 이동 편의성이 고려되어야 합니다. | 걷는 거리가 좀 있어요. 쉴 곳을 봐두시면 좋아요. |
| 죄송합니다. 요청하신 내용을 이해할 수 없습니다. | 제가 잘 못 알아들었어요. 장소 이름을 알려주실 수 있을까요? |
| 안전하게 이용 가능합니다. | 공식 자료 기준으로는 조건에 맞아요. |
| 정보 미확인 상태입니다. | 아직 확인된 자료가 없어요. |

**12-3. 문장 규칙**

- 한 문장 40자 이내
- 요약은 두 문장 이내
- 명사만 늘어놓지 않는다 (`휠체어 대여 가능 여부 확인 필요` ✗ → `휠체어를 빌릴 수 있는지는 확인이 필요해요` ✓)
- 해요체로 통일. `~습니다`와 섞지 않는다
- 사용자를 부르지 않는다. 주어를 생략한다
- `어머님`, `할머니` 처럼 가족 관계를 짐작해서 부르지 않는다
- `없음`과 `확인 안 됨`을 절대 같은 말로 쓰지 않는다

**12-4. 기존 문구도 손본다**

`index.html` / `script.js` 안의 아래 문구가 대상이다.

```
"확인되지 않은 정보는 따로 알려드려요."          → 유지 (자연스러움)
"현재 공식 자료에서는 다음 정보를 확인하지 못했어요."  → "아래 정보는 공식 자료에 안 나와 있어요."
"공식 자료에서 전체 보행거리 정보를 확인할 수 없습니다." → "얼마나 걷는지는 자료에 안 나와 있어요."
"관광지와 궁금한 점을 입력해 주세요."             → "어디를 가시는지 알려주세요."
"가족에게 필요한 여행 정보를 확인하고 있어요…"      → 13-1의 3단계 문구로 교체
```

전체를 훑어서 같은 기준으로 정리하라.

13. 인터랙션과 애니메이션 — 절제

**13-1. 로딩은 진행 상황을 말한다**

한 문장 고정 대신 단계별로 바꾼다.

인디케이터는 점 3개가 순서대로 커지는 정도로 충분하다.

**13-2. 답변 등장**

`opacity 0→1`, `translateY 12px→0`, `180ms`. 카드당 한 번만.
섹션마다 순차 등장시키지 마라. 읽기를 방해한다.

**13-3. 반드시 지킬 것**

```css
@media (prefers-reduced-motion: reduce) {
  * { animation: none !important; transition: none !important; }
}
```

**13-4. 쓰지 말 것**

- 자동 재생 반복 애니메이션
- 카드 hover에서 크게 움직이는 효과
- 복사·전송마다 뜨는 축하 효과
- 소리
